## 4. 内部检查点：通过后自动前进

### A｜网络与持久资产底层

检查并锁定 FishNet 与传输版本，先本机 Host/Client，再独立设备。本轮 Steam 是最终连接候选，但不让账号缺失阻塞其他工作。

实现稳定玩家标识、单一物品归属、拾放/掉落、独立钱与交易、世界存档、加入/离开/迟加入。把存档尽早纳入而非做完游戏再补。M0 输入、持有关系与角色控制不能只加一个网络组件就算迁移完成。

A 闸门：实际两个进程争抢同一 ID 仅一人成功；重复出售仅一次入账；正常保存重开资产一致。未通过先修复，不堆其余内容。

### B｜矿坑与完整采矿循环

营地/初级坑灰盒；房主确定矿体内容，有限单元实际挖空；资源、维修、梯子、大矿单人慢拖/双人协助、收购/转账。保存坑与设施。允许正常操作者把矿带回来，不依赖调试传送。

B 闸门：两人实际从探测/挖掘到卖出/分账完成；向下挖、爬梯返程并读档保留坑；不出现破产无法继续。

### C｜角色样件与社交/原石

实际打开四图、建立一个绿色矿工和可识别的营地角落，加入持物/挥镐/鼓嘴表现。粗检/开窗/开石、口头交易、抢夺和短晕、烟酒动作、两人托管对赌桌。

C 闸门：朋友从画面能识别动作；嘴槽物品、赌局和攻击无重复归属。生成参考图不算模型；静态角色不算动作完成。样件可以留给用户集中反馈，但在已有方向明确时继续实施，不无限等审美确认。

### D｜一段成长与出行

个人工具升级、公共修车/道路贡献、简化四座车、短车路、小进阶坑。数据调出一段目标清楚的进度。加入车辆/解锁/进阶区的持久化。

D 闸门：非调试玩法可以修车→实际驾驶/乘坐→到进阶区→带货回营地→退出重开保留结果；单人也有路径，未上车者不被强行传送。

### E｜异网和基础语音

沿 FishNet＋FishySteamworks＋Steamworks.NET 候选路线核对维护者依赖。先验证可用 AppID、账户权限、测试访问条件，再做 Steam 房间与邀请、传输、加入错误和语音。

语音要做到真实麦克风→编码/发送→其他客户端接收/播放；显示说话状态、静音、设备选择和近距离衰减。只调用录音 API 不是完成。

E 闸门：真实不同设备和不同网络至少完成一次往返交互及双向语音；之后安排四人中国/美国条件测试。模拟延迟不是中美实测；本机四窗口不是四个账户实测。

### F｜雏形交付

修复阻止完整流程、丢钱/复制、存档损坏、主要交互失效的问题；完成最终构建、实际启动、适用回归与进度总结。再安排用户约一小时真人测试，收集后可以继续下一轮修复；不要求自动化代理证明游戏“永远耐玩”。

## 5. 工具和资产策略

已经工作正常的编辑器自动化不重复做全面审计。MCP 失败则先定位，必要时用项目内 Editor 脚本继续，不改全局配置和无关项目。允许免费安装必需的 Blender/依赖，但先检查已装版本，不能为本轮买模型/订阅。

- 简单工具、木屋、岩石、柜台、梯子、车体：Blender Python/可复用建模脚本或已授权素材，保持统一比例和材质。
- 角色：按用户三视图做可动画的简化资产，可用 Generic 骨架/程序动作；不强求套 Humanoid 导致豆形身体变长脖子。手和嘴有挂点，形变能表达鼓嘴。
- AI 生成服务只在已有有效授权与无新增扣款的实际能力范围内使用。缺 API/额度时不假装能全自动生成，也不自动改用计费 API key。
- 资产进入引擎要检查比例、pivot、材质、碰撞、骨骼/握点、LOD（确有需要再做）、运行和构建。不要把拼图作为贴在角色前的图片冒充3D。
- 参考图留在本包 `References`，不要为了“看图”全部放进运行时 Resources 增加包体。若既有 `AssetsSource` 和资产台账，复用；不要开第二套矛盾目录。
- 一个小样先在游戏里验证，再重复生产。概念图的高精细缝线/污渍不要求逐像素复刻；轮廓、角色身份、色彩和可读性不能被随意替换。

## 6. 预算、权限与 Steam 外部阻塞

新增开支按 0；现有用户订阅允许按正常账户限制使用，不自动购买额外额度。免费代码/工具从可信官方或维护者渠道获取。购买、付费账户、Steam Direct、商店/测试公开发布等必须本人明确确认。

用户“不清楚 AppID”不是“没有”，先查项目已有合法配置与可访问账户，不扫描无关私密文件；浏览器登录/验证码/授权由用户处理。当前不确定的事项在首次预检就汇总报告一次，不等所有美术完成才提出。

没有有效 Steam 项目/访问条件时：
- 继续完成 A—D 和其他不依赖项，保留局域网构建；不要每分钟轮询账户状态。
- E 列为真实外部阻塞，给出最小操作、需要的权限/费用确认和继续条件。
- 不把示例 AppID 当成用户自己的项目，不据此宣称已完成正式测试分发；示例仅在当前官方/维护者允许范围内作明确标注的开发烟测。
- 不未经同意租云服务器、安装组网/VPN 服务、改路由器/防火墙或换全套网络框架。
- 不因为预算缺失就默默取消异网与语音验收。若最后只这些受阻，交付“可用本地候选＋外部待办”，不能标“完整目标通过”。

禁止 force push、hard reset、覆盖陌生工作、删除真实存档、关闭整个系统安全设置、公开私库或凭证。只操作本项目进程；必须停止本项目 Editor 时先保存，不杀其他项目。

### 7.2 多进程、异机和真实输入

先 Host＋1 Client，然后 Host＋3 Clients；都检查对应独立身份/存档目录/端口/窗口和日志。本机负载过高先拆分测试或降低测试分辨率，不声称跑不了四进程等于游戏不能四人。

连接矩阵分开记录：本机多进程、两台设备局域网、不同网络两人、不同网络四人、中美组合、语音双向。可在 Development 测试延迟/丢包，如 100/200/300ms RTT 与少量丢包作为压力样例；必须注明模拟条件，不宣传成实际中美延迟。

用户电脑已有约16GB内存记录，先重新检查实时资源。避免同时开 Blender、多个 Editor 和四个高画质实例。性能先测实际 FPS/帧时间、内存/显存和CPU/GPU耗时，再定目标；不杜撰最低配置/保证稳定60帧。

脚本输入、自动玩法驱动、窗口启动、人工键鼠分开报告。真实人工尚未做就是待测，不因为14项逻辑测试过就勾全部体验。

### 7.3 真人一小时建议

用户和四名朋友总人数可能为五，最大同房四人，轮换一次即可。

约5分钟进入/语音；15分钟正常挖矿和梯子；15分钟搬运/卖矿/分账/抢夺；10分钟嘴藏/烟酒/赌石；10分钟升级/短车程/进阶矿；5分钟保存退出、部分玩家先回再重进。时间只是测试安排，不改变持久世界规则。

收集真正的问题：卡哪里、是否看得懂、是否因重复被打放弃、是否有主动协作/再出发。不能在没有朋友参与的情况下生成这类结论。若当前实现没法覆盖一小时项目，明确未覆盖项，下轮继续，不假装完成。

## 8. 减少空转，允许接续

- 计划—实现—测试—修复—记录循环；每个内部检查点完成后自动推进，不为小改动问“继续吗”。
- 独立资产/代码可以有限分工；场景、Prefab、包清单、存档结构有唯一整合者。没有必要就不新增代理管理平台。
- 大编译/下载有合理超时，完成后读取真实输出；不要短间隔无限轮询。
- 同类失败反复出现时形成一个假设并验证，必要时换项目内实现。不要重复无效命令耗额度，不让修工具变主业。
- 临近额度/上下文边界时保留已测状态、未完部分、最后错误、具体下一步。恢复时先读任务和 diff，不重建整个项目。
- 对付费、账号授权、真正无法判定的破坏性取舍再问用户；已授权的普通数值和实现细节自行决定。
- 总目标不是“无论如何永不停止”。达到候选交付、所有剩余项都是外部阻塞、或额度限制时清楚停止/接续。
