# 直接发给 Codex：M0 启动任务

你现在接手一个新独立游戏 GoldCamp，不是我以前的任何网站、小程序或业务项目。请先读取本目录提供的《淘金营地_完整开发提案_v0.1.md》和 AGENTS.md 模板。提案是待实现设计，不是已有工程进度。

## 本轮目标

只完成 M0：把项目、编辑器自动化、测试／构建和最小灰盒底座真正跑通。不要一次写完整游戏，不制作正式角色，不接赌场、不做发布，不创建运行时 AI 服务。

## 执行

1. 核对当前工作目录、已有文件和 Git 状态；不能覆盖未知现有项目。检查 Windows、硬件、可用磁盘、Unity Hub／Editor、Codex、Git、Blender 的实际情况。记录到 docs/ENVIRONMENT.md。不要把未安装的软件写成已具备。
2. 优先 Unity 6.3 LTS＋URP＋C#，选择当前机器能够安装／授权的补丁版本并记录。登录和许可若需要本人操作，说明最小操作；其他能做的继续，不绕过验证。
3. 在本项目内创建目录、README、.gitignore、实际适用的 LFS 策略和 docs/{GDD,TDD,ROADMAP,STATUS,DECISIONS,TEST_PLAN,ASSET_REGISTER}.md。提案中任何未来脚本必须标为未创建，直到实际实现。
4. 配置一个 CoplayDev MCP for Unity 桥接并做读 Console／创建或查询对象的最小验证。先核对官方维护者说明和依赖版本。若当前环境不兼容，使用项目内 Unity Editor 脚本替代；不为强行接桥接器而重写工程或不断更换引擎。
5. 创建灰盒场景：地面、少量障碍、第一人称移动与视角、一个可拾取和放下的矿块、简单交互提示、一个收购点占位。必须有落地反馈，但不做真实采矿和网络。
6. 建立最小纯规则模块和自动测试，至少验证拾取／放下不能让同一物件有两个归属。若尚未接完整经济，不写虚假经济通过报告。
7. 创建可重复 Windows Development 构建入口、测试入口及清楚的运行说明；实际执行适用的测试和构建，记录命令、用例数、日志和产物位置。打包后实际启动验证，无法启动则说明实际阻塞。
8. 更新 AGENTS.md 的真实路径与版本；更新 STATUS，区分已实现、已测试和待测试；给出 M1 的最小接续任务。

## 验收

- 工程在实际 Unity 版本中可打开，没有未处理编译错误。
- Windows 构建可以运行，玩家能走动、观察、拾起／放下矿块。
- 测试真实执行，不把零用例／静态阅读算通过。
- .meta 保留；无秘密凭证、无无关项目文件混入。
- 编辑器自动化可用，或已证明项目脚本替代路径可用。
