# GoldCamp 项目规则

本文件是项目模板；M0 必须用真实工程状态补齐工具版本、命令和路径。未存在的入口不得写成已验证命令。

## 唯一目标与边界

在本独立工程制作 Windows／Steam、1–4 人、第一人称卡通低多边形淘金游戏。默认无运行时 LLM、无专用云后端、无全球账户经济。
保留个人资产、私下发现、合作搬运、口头分账可背叛、短击晕抢夺、原石固定真相、嘴槽藏物。
以当前里程碑为范围；新想法记入 Backlog，不自动实现全部提案。不修改相邻项目、共享全局工具规则或既有 Git 历史。

## 事实优先级

源代码、真实 Git 状态、Unity Console、实际测试结果、运行构建 > docs > 历史聊天和上一轮文字汇报。
开始先读取 docs/STATUS.md、ROADMAP.md、DECISIONS.md、TEST_PLAN.md；文件不存在时如实初始化。
不能假称已安装、已登录、已跑异机测试、已获商用授权或已发布。

## 工作方式

一次自主完成当前里程碑内的实现、debug、回归与文档更新；不为每个微小修改等待确认。
真正需要账户验证、购买、破坏性变更或正式发布时停止该动作；能独立完成的其他任务继续做。
不把工程交给另一个聊天机器人代为写核心代码；Codex 直接修改本地工程。MCP 用于操作编辑器，不替代源码。
每轮优先解决实际阻断、状态一致性和玩家体验；不做无关重命名、装饰截图审计或未经要求的全栈重构。

## 引擎和工具

Unity 6.3 LTS／URP／C# 为候选；记录实际安装补丁及依赖版本并锁定。
联机候选为 FishNet＋FishySteamworks＋Steamworks.NET；M1 兼容性试验通过后才定版。
仅使用一个 Unity 编辑器 MCP 桥接；不可用时用项目内 Editor 脚本完成等效操作。
保留 Assets 与对应 .meta；不提交 Library、Temp、Obj、构建缓存或秘密凭证。
源模型和大二进制按实际 Git LFS 策略处理；付费素材不可公开再分发。

## 必须保持的数据约束

房主对钱、物品、原石生成／开石、抢夺与结算作最终判断。
每个稀缺物品有唯一 ID，世界／手／包／嘴／储物柜之间只能存在一个有效位置。
每笔交易有请求 ID，重复提交不得再次扣款或发款。
原石在生成时确定内容；换人、掉落、断线、读档不能重抽。
存档中的余额、物品位置及已处理交易要一致恢复；正常退出与崩溃恢复分别验证。
只向客户端发送其当前应知的信息，不能默认广播完整原石真值和全部背包。
好友房房主仍可能修改本地数据；不承诺对恶意房主绝对防作弊。

## 验收

先证明最小可玩闭环，再做正式美术。每个玩法修改都增加对应回归测试或清晰手工验收。
自动测试必须记录实际命令、用例数量、失败数和结果路径；零测试不算通过。
构建成功不代表运行成功；同机多实例不代表不同网络／Steam 账户联机通过。
真实四人体验必须由真人试玩；Codex 不得代写“玩家觉得好玩”的结论。
只在权限明确且测试通过后提交；push 需要用户明确授权及已核验远端。禁止 force push、重置他人修改、静默删测试。

## 每轮结束的简明报告

1. 实现了什么和未完成什么。
2. 实际修改范围、版本／分支／commit（确实存在时才写）。
3. 实际测试／运行结果及证据路径；未执行项单列。
4. 当前剩余风险、需要用户完成的最少操作。
5. docs/STATUS.md 中写清下一轮最小任务。
