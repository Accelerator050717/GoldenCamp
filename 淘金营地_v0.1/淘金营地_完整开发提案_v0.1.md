# 01｜可行性：可以独立做，但不能一键交付

**判断：由你担任制作人和主测试者，Codex 承担主要程序工作，结合现成资产、AI 初稿与少量人工修整，完成本提案缩小范围后的可售版本，是合理的开发路线。** 这不是成功概率保证，更不等于当前全部脑洞都能无代价地放进首版。

你不是完全没有工程经验：已有 Codex、项目联调、Git 和功能验收的使用基础。真正的新领域是游戏引擎中的场景与资源、交互手感、多人同步、3D 资产处理，以及面向陌生玩家的打磨。不要把“第一次完整开发游戏”理解成需要从编程第一课重新开始，也不要把网页项目能运行等同于游戏已经好玩。

Codex 具备本地代码工作流和 MCP 工具接入方式；Unity 的第三方 MCP 桥接项目提供场景、资产、脚本与测试操作。这为自动化提供了入口，但项目实际兼容性、操作成功率与生成质量仍须本地验证。[S03][S04][S06]

| 工作 | 主执行者 | 完成证据 |
|---|---|---|
| C# 玩法、存档、工具脚本、测试、构建 | Codex | 实际源代码、测试结果、可运行构建 |
| 场景摆放、Prefab 装配、批量导入 | Codex＋Unity MCP／编辑器脚本 | 引擎内对象状态与试玩，不只文字报告 |
| 道具／场景模型初稿 | 现成资产、Blender 脚本、Meshy | 导出文件与游戏内检查 |
| 角色、动作、音效和风格统一 | 工具初稿＋你验收；必要时专项外包 | 不穿帮、看得懂、听得清、玩得顺 |
| 好不好玩、朋友是否愿意再来 | 你＋真实玩家 | 行为观察、复玩、录屏与问题记录 |
| 账户验证、购买、法律主体、商店发布 | 你 | 真实账户与明确人工授权 |

**独立开发不等于禁止买资产或请人修一个动作。** 当一个专门问题持续阻塞主线，购买合适资产或一次性请专家处理，可能比反复消耗 Codex 用量更划算。不要预先承诺“全部由 AI 制作”作为产品卖点。

**当前不做的承诺：** 不承诺模型生成一次就可商用上线；不承诺一个月完成；不承诺无限游玩时长；不承诺低多边形等于低开发难度；不承诺支持全球低延迟、房主无缝迁移或绝对防作弊。

# 02｜产品定位与必须保留的体验

| 项目 | v0.1 建议基线 |
|---|---|
| 平台 | Windows PC，优先 Steam；键盘鼠标首发 |
| 视角与画面 | 第一人称、3D 卡通低多边形；别人能看见你的完整角色 |
| 人数 | 1–4 人；核心为 2–4 名认识的朋友，单人可走完赚钱和解锁流程 |
| 世界 | 一个持久营地＋三个逐步开放的小采区；不是无限开放世界 |
| 一次游玩 | 以 30–90 分钟的朋友聚会为体验设计目标，不是强制时限 |
| 收费 | 完整买断；首版无订阅、无运行时大模型、无真钱购买筹码或提现 |
| 联机 | 私人／好友邀请房；房主电脑同时运行游戏与权威逻辑 |
| 风格 | 成年矿工、卡通击晕、贪财与恶作剧；不是硬核生存或严肃赌博模拟 |

**四个产品支柱。** 第一，随时能边聊天边干活；第二，财富是可拿、可藏、可展示的东西；第三，合作能带来好处，背叛也有实际空间；第四，被坑后很快能重新参与，而不是长时间旁观。

玩家的基础循环：找矿 → 挖掘／淘洗 → 决定自己带走还是求助 → 隐瞒、检测或交易 → 搬回营地 → 开石或出售 → 自己决定分不分钱 → 买工具、收集与显摆 → 探索新采区。

**首发宣传必须能拍出的三个场面：** 两个人搬大金块，卖完收款者转身就跑；用探测器扫到朋友鼓起来的嘴；四个人围着切石台，卖掉原石的人发现里面开出大奖。它们必须由真实规则产生，不能只是预先播放动画。

主业也必须独立成立。每轮测试都安排一段不抢人、不赌博的正常采矿，验证找矿、操作工具和发现新东西是否仍然有趣。否则恶作剧只是在替枯燥主业遮丑。

# 03｜核心规则：让朋友产生故事，系统只负责执行事实

## 3.1 资产分开，口头承诺不强制执行

发现矿点不自动全队公告。个人余额、背包内容和未分享的检测结果默认不公开。收购台向附近玩家展示成交价与收款人，不在整个世界发布财富排行榜。

谁完成出售，钱进谁的账户；玩家可以手动转账。游戏不强制均分，也不自动追讨口头分账。合作前付定金、让可信的人收款、原地分割矿石，都是玩家自行选择的办法。

**合作与独吞都有路径。** 大矿块一个人能慢拖，两个人可以更快搬；用推车独运需要买工具和承担路途风险；切开分拿更好控制，但完整出售可有溢价。完整溢价是明确的虚构游戏规则，不用伪装成真实矿业知识。

## 3.2 可抢的东西与长期积累分开

| 类别 | 默认规则 |
|---|---|
| 随身矿石、原石、展示中的未入库战利品 | 可以被丢落、捡走、交易或短暂抢夺 |
| 已入账货币 | 不能靠击晕直接清空；只能持有人花费／转账／自愿下注 |
| 基础工具与已解锁能力 | 不会因一次抢夺永久失去；基础挖掘途径始终可用 |
| 个人储物柜 | 先做存档内个人保管空间；不首发做复杂开锁系统 |
| 摆在公共区域的物件 | 可互动；重要收藏必须有明确的展示／收回规则 |

击晕只持续短时间，恢复后有短暂保护，避免无限连控。抢口袋需要近距离动作，不是瞬间吸走全部背包。首版用简化动作＋掉落反馈，不做全身高精度格斗或致死射击。房间主人可以关闭玩家伤害／抢夺供不同朋友群使用，但默认体验保留用户提出的恶作剧空间。

## 3.3 嘴里藏东西是玩法，不是完整消化模拟

先做“含一颗小物件 → 脸颊鼓起 → 可主动吐出 → 被碰撞可能掉落”。探测器给出模糊异常，不能列出对方背包。以后再考虑吞下、定时取出和卡通厕所转场；此扩展不进入第一轮原型。

规则要可见：大小有限、占用嘴部槽、别人能观察到异常；不能让吞下成为无代价、永久安全的最优解。玩家使用外部语音也不影响这些规则。

# 04｜赌石、经济与复玩的来源

## 4.1 原石“先有真相，再逐步揭晓”

每块原石生成时就确定唯一编号、内部类别、品质、瑕疵和可开窗区域。检测、交易、掉落、转交、含嘴、重连、读档都不能重新抽奖。玩家可以获得不同程度的线索，但系统中的真实内容保持一致。

首版切石不做任意网格切割。将一块原石制作成外壳＋若干预定义窗口＋内部核心；开某个窗口就是揭示对应的确定信息。全开后展示对应模型和价格。这样保留猜测与揭晓，控制制作和同步复杂度。

检测器不显示准确价格，只给“晶体反应”“杂质偏多”“信号集中在一侧”等有限信息。卖家可以透露、夸大或隐瞒，不由系统替他说谎。购买者付钱后，拿到的是同一块原石。

## 4.2 三种下注情境，先只实现必要的一种

自己选择稳价出售还是支付加工费开石；朋友之间买卖不确定原石；自愿把两块原石放到桌上，比最终估值并结算约定赌注。第三种作为正式版候选，原型只需开石与手动转账即可验证聚会乐趣。

**明确区分两种“赖账”。** 普通搬运合作后的口头分账不强制兑现；专门赌桌若显示“已托管赌注”，则开局前锁定筹码、揭晓后自动结算，不能演出已结算却没有付款。也可以提供不托管的口头对赌，但界面必须让大家知道。

## 4.3 钱花在哪里

能力升级：探测、采集、搬运、加工、藏匿的信息差工具。收藏升级：矿石图鉴、尺寸纪录、个人展示架与造型。区域升级：取得进入新采区的资格，发现不同矿点和组合问题。永久升级尽量改变操作方式，而不只是线性提高攻击力。

防止破产后没事做：基本铲子与基础矿点不收费；不强制吃饭、交房租或每日还债。富人可以买便利和显摆，不买永久压制朋友的战斗数值。

首轮平衡采用数据表，不把价格写死在脚本中。使用普通／稀有／惊喜收益的分布，记录检测费、加工费、搬运时间、出售收益、抢夺频率。不得根据玩家是否付费或近期输赢暗改原石结果。

复玩来自新工具改变旧操作、矿点位置变化、不同路线与朋友协商、收藏目标。不是承诺无限内容。若玩家第二次就只蹲收购台抢人，先修经济与采矿体验，不靠加三十种帽子掩盖。

# 05｜版本范围：原型、精品样段与可售 1.0 不混为一谈

| 范围 | 四人玩法原型 | 垂直切片：一小段接近成品的体验 | 初版 1.0 建议上限 |
|---|---|---|---|
| 场景 | 灰盒营地＋一片矿地 | 一片打磨好的河谷 | 一个营地＋三个小采区 |
| 角色 | 胶囊／简模，能区分玩家 | 一个统一骨架＋四种外观 | 同一骨架，增加少量帽子与配色 |
| 主业工具 | 铲、探测器、搬运交互 | 加小推车与切石台 | 约 8–10 种功能工具，避免重复 |
| 矿物 | 金粒、大块矿、几类原石 | 4–6 类可区分收获 | 约 8 类基础矿物＋品质／形状变化 |
| 社交 | 拿取、转账、击晕、嘴槽 | 表情／道具动作、交易反馈 | 约 4–6 种辅助／捣乱道具 |
| 赌博 | 开石、玩家手动交易 | 可围观的切石揭晓 | 原石对赌；传统赌场不默认加入 |
| 长线 | 保存每人余额与工具 | 一条完整升级目标 | 区域、工具、收藏与个人展示 |
| 网络 | 早期四进程＋真实异机 | Steam 好友联机与基础语音 | 重连、迟加入、设置和完整错误提示 |

这些数量是防止范围失控的初始上限，不是必须凑够的配额。删掉不好玩的工具，胜过用十种同功能工具凑内容。

**首版明确不做：** 无限可挖地形、真实水体和泥沙流体、真实翡翠体积切割、车辆全物理驾驶、复杂绳索联动、公共匹配、跨平台联机、全球持久经济、Steam 市场交易、房主无缝迁移、长期专用服务器、大模型 NPC、复杂剧情、昼夜生存惩罚。

单人可以采矿、加工、赚钱、推进；大件允许慢拖或切开。不要让 1 人模式在“两人强制抬物”处卡死。好友缺席时，其资产保留，但默认不替其承诺持续离线收益。

# 06｜引擎决策：首选 Unity，不同时试三个引擎

**建议基线：Unity 6.3 LTS＋URP＋C#。** Unity 官网目前列明 6.3 LTS 支持至 2027 年 12 月。M0 安装该分支的合适补丁版后，记录完整编辑器版本；项目过程中不追逐每个新版本。[S01]

URP 是 Unity 的通用渲染管线，可将其理解为本项目统一的画面配置。选择它是为了服务风格化小场景，不开局追求电影级渲染。角色控制、UI、场景、物理都先走普通 GameObject／组件工作流，不引入 ECS 等额外架构。

| 选择 | 本项目决策依据 | 不选／不默认使用的原因 |
|---|---|---|
| Unity | C# 文本代码适合 Codex；已有可核验的编辑器桥接、网络和资产路线 | 必须管理包版本、.meta 与资源依赖；不是零维护 |
| Godot | MIT 许可，可做此类游戏 | 本提案不再建立第二套 3D／Steam 工具链；不是说它技术上做不了 |
| Unreal | 有完整引擎能力和明确游戏许可 | 本项目不需要以其高端渲染为核心；不增加蓝图与 C++ 双工作流负担 |

Godot 的 MIT 许可、Unreal 的许可入口见官方资料。[S31][S32] 以上取舍是项目适配判断，不是对三个引擎的绝对排名。

Unity Personal 当前有 20 万美元收入／融资门槛，具体适用主体与资格以许可为准；Unity 已取消 Runtime Fee。不要把“暂时符合免费条件”写成永远零引擎成本。[S02]

**网络首选候选：FishNet＋FishySteamworks＋Steamworks.NET。** FishySteamworks 官方仓库明确依赖 FishNet 与 Steamworks.NET，并提供通过 Steam relay 的点对点模式。只有完成 M1 的实际版本组合测试，才将具体版本定为项目基线。[S14][S15]

不同时安装 FishNet、Mirror 和 Netcode for GameObjects。若首选在干净工程里不能通过关键连接／断线测试，记录阻塞原因再评估替换。必须先证实是框架／适配器问题，而不是新手项目配置错误。

# 07｜每一部分用什么工具

| 环节 | 主工具 | AI 如何参与／交付物 | 费用与注意 |
|---|---|---|---|
| 设计与复盘 | ChatGPT＋项目 Markdown | 规则、任务、问题分析；由你决定取舍 | 复用已有工具，不再买同功能助手 |
| 程序与自动化 | 本地 Codex＋Git | 写 C#、编辑器脚本、测试、构建脚本 | 订阅用量与 API-key 计费分开核查 [S03] |

| 精确建模／修模 | Blender＋Codex 生成的 Python | 造铲子、木箱、支架；批量处理尺寸、材质、导出 | Blender 与脚本能力见 [S07][S08][S30] |
| 独特道具初稿 | Meshy；Tripo 仅为替代候选 | 概念图／文字到 3D；先网页验证，再考虑批量 API | 只买一家；检查实际下载与商用许可 [S09–S11] |
| 通用场景资产 | Kenney／已授权统一风格资产包 | Codex 导入、生成 Prefab、摆放 | Kenney 官方资产页通常为 CC0，仍存附带许可 [S12] |
| 角色动作 | Unity Animator＋现成合法动作；Mixamo 条件适用 | 重定向、状态机、抓取定位；特殊动作需修整 | Mixamo 有账户地区限制，不能当成必然可用 [S13] |
| 音效 | 实录／合法音库＋Audacity；ElevenLabs 可选 | 生成缺少的短音效，剪切、归一化 | 生成商用音效须用适用许可；不默认音乐也同许可 [S28][S29][S35] |
| 多人语音 | Steam Voice＋游戏网络传输 | Codex 实现采集、发送、播放和距离衰减 | 原型可用外部语音；上线前做麦克风设置 [S17] |
| 测试 | Unity Test Framework＋多实例构建 | 自动检查逻辑、场景、存档与网络脚本 | 自动测试不等于真实朋友体验测试 [S18] |
| 版本管理 | Git＋GitHub 私库＋Git LFS | 差异检查、版本标记、文档同步 | 大型模型文件／音频文件纳入 LFS，配额另核查 [S19] |
| 录制与宣传 | OBS＋DaVinci Resolve | AI 辅助字幕和脚本；展示真实游戏录像 | 有免费工具路线，不用伪造实机画面 [S33][S34] |
| 发布与测试分发 | Steamworks＋Steam Playtest | Codex 准备构建与文案；你审核、上传授权和发布 | Steam Direct、审核与时间规则另列 [S21–S23][S26] |

**AI 接入不等于所有工具都必须走 API。** 首批十件资产手动选择、导出，往往比先写一套生成平台集成更省事。自动化重复、可验证的步骤；把风格选择与手感判断留给人。

首日仅装引擎、Codex、Git 和一个 Unity 桥接。Blender 在资产阶段加入，AI 建模订阅在确定物件规格后再开。不要同时维护五种 MCP，给每轮上下文增加不必要负担。

# 08｜环境准备与新手需要掌握的最小知识

## 8.1 你亲自完成的第一次设置

准备一个与现有医疗、学校或工作项目完全分离的本地目录，例如 D:/Games/GoldCamp（仅示例，不是你电脑上的已知路径）。避免放在自动同步网盘目录中。创建独立私有仓库，确认所有待导入代码和素材都有权使用。

安装 Unity Hub、选定的 Unity 6.3 LTS 补丁版及 Windows 构建组件；通过自己的账户确认引擎许可。用 URP 模板建空项目，先在编辑器运行，再打出一个能启动和退出的 Windows 构建。账户登录、许可接受与付费由你操作，不让 Codex 冒充完成。

安装／使用现有 Codex 本地客户端，指向新工程；配置 Git 与大文件策略。添加一个选定版本的 Unity MCP，验证最小操作：读场景 → 创建带碰撞的方块 → 进入运行 → 读取 Console → 保存场景。连接失败则用 Codex 写 Unity Editor 脚本执行同一件事，不把桥接修复变成长期主线。[S04][S06]

## 8.2 最少理解这些词，不必先系统学完引擎

Scene 是关卡／场景文件；GameObject 是场景中的对象；Component 是挂在对象上的功能；Prefab 是可以反复使用的物体模板；Collider 是碰撞外形；Rigidbody 是参与物理模拟的组件；Material 是表面画法；Animator 管理动作切换；Inspector 用于查看参数；Console 显示日志与错误；Build 是能离开编辑器运行的游戏包。

你至少亲手做一次：移动相机、选对象、改一个 Inspector 数值、播放／停止、找到 Console 错误、打开构建。目的不是让你取代 Codex 编程，而是你能区分“场景没保存”“脚本报错”“打包不包含场景”和“功能没有实现”。

## 8.3 硬件不是现在就买新的

本提案未读取到你当前 CPU、内存、GPU、显存和磁盘的可靠规格，因此不判断现有电脑一定足够。作为开发目标建议使用 SSD，尽量有 32GB 内存便于引擎＋Blender＋多实例测试；16GB 可先做小原型。此为工作配置建议，不是官方最低要求，也不是硬件购买清单。

先由 Codex 读取机器规格、可用磁盘与工具版本，保存环境报告。你之前提过电脑显示异常，若尚未解决，应先保证机器稳定并备份；不要把硬件故障误判成游戏逻辑错误。真实 Steam 四人验收需要朋友的设备与账号，单台机器多开不能替代。

# 09｜Codex 的工作方式：一次完成一个可验收模块

**适合你的节奏：阶段目标一次说全，Codex 自行实现、debug、跑测试并交付；不要每改一个文件都等你确认。但整个游戏必须分阶段，而不是一个无限长任务。**

每轮固定流程：读取当前源码和状态 → 选一个明确任务 → 写／补相应测试 → 实现 → 编译 → 跑测试 → 打包 → 记录证据与剩余限制 → 在已获授权的前提下提交代码。支付、删库、重写 Git 历史和公开发布仍需独立授权。

项目根目录保留简短 AGENTS.md，写不变量和入口；长设计放 docs，当前任务放 TASK.md，真实进度放 STATUS.md。Codex 对 AGENTS.md 的使用有官方文档；不要依赖聊天记忆作为唯一项目知识。[S05]

同一时刻只有一个写入者修改主 Unity 场景和关键 Prefab。并行助手可以审查代码、写独立测试、处理不同资产，但不能多人同时改同一个场景文件、包清单和网络基础层。不要每次开新对话都重新扫描所有历史资产。

**标准汇报只有六项：** 已实现的行为；改变的文件；实际执行的命令与结果；可运行构建路径与版本；没有验证的部分；下一条最重要的阻塞。没有真的运行四人 Steam 测试，就必须写“未测”，不能把本机四窗口称作真实联机已通过。

**模型用量策略：** 复杂联机／存档问题用当前可用的强推理配置；重复改名、资源导入、格式化用较轻配置或脚本。读取相关文件，避免整库反复塞进上下文。首次明确用现有登录额度还是 API-key 计费，设置人工预算线，不偷偷切换付费来源。[S03]

**界面控制的降级路线：** MCP 可用时用 MCP；不可用时用受版本管理的 Editor 方法；必要的许可证、麦克风选择和视觉验收由你操作。不要假设任何 Codex 窗口都天然具有 Unity 控制权限，也不要把鼠标坐标点击录制当成唯一自动化方案。

# 10｜联机技术：房主主持，不先养一套云服务

玩家电脑中有一个房主，同时运行游戏画面和权威逻辑；另外三台电脑发送操作请求并接收状态。Steam 房间负责发现／邀请，网络传输负责送数据，FishNet 负责网络对象、调用和状态同步。它们是不同层，不是“装 Steam 插件就完成联机”。[S14–S16]

**不自建的服务：** 首版不需要登录网站、在线数据库、排行榜服务器、模型推理服务器或专用游戏服务器。Steam 中继不是替你保存世界，也不会替你运行挖矿规则。房主上传能力、机器性能和双方网络会影响体验。[S15][S16]

## 10.1 哪些事必须由房主决定

矿点产物生成、物品当前所在位置／容器、拿取与抢夺、成交、账户转账、原石真相、切开结果和存档，由房主逻辑确认。客户端不能提交“我有一千块钱”，只能提交“请求出售这件物品”。

移动与手部表现优先响应本地输入，其他角色做平滑同步；矿石与关键物件保持单一权威。不要让四台机器同时对同一块矿石作最终物理裁决。具体插值／预测参数由 M1 实测决定，不在文档中虚构已调好的参数。

## 10.2 搬运看起来有物理，不等于所有东西都要全物理

首版采用持有锚点和固定交互范围；大矿块只有一个权威驱动，参与者人数影响速度与稳定性。推车先是简化可推动载具，矿物放进去后进入稳定槽位，不模拟几十颗金粒连续碰撞。

击晕以同步状态、方向和恢复时间为准，角色局部抖动／布娃娃作为视觉效果。不让每根骨头成为持续联网刚体。屏幕上撒出的灰尘和碎屑多数为本地效果，只有有价值的掉落需要网络编号。

## 10.3 从第一个技术原型开始，按证据推进

先用本地传输做 2–4 个实例，便于 Codex 自动测试；随后用至少两台设备和两个 Steam 账号测试真实路径，最终四人异网测试。FishySteamworks 文档明确指出，同一 Steam 身份在同机双构建上的测试不能替代两个设备／账号。[S15]

房主正常退出先完成存档，然后所有人退出房间；房主崩溃后恢复到最近一致存档。首版不无缝迁移房主。对用户明确说明，不把这点隐藏到发售后。

# 11｜数据、隐私信息与存档：最不能含糊的部分

## 11.1 最小模块划分

| 模块 | 职责 |
|---|---|
| Core | 物品、货币、交易、原石与规则，尽量可脱离场景测试 |
| Gameplay | 移动、工具、挖掘、拿取、搬运、击晕和嘴槽 |
| Networking | 房间、身份、权限、同步与重连；本地／Steam 传输适配 |
| Persistence | 世界快照、交易记录、版本迁移、备份与恢复 |
| Presentation | 动画、音效、VFX、界面与反馈，不自行修改经济真相 |
| EditorTools / Tests | 场景生成器、资产检查、构建工具和自动验收 |

物品至少包含 itemId、definitionId、位置或持有者、数量、状态版本；原石另有固定隐藏内容和已揭示信息。玩家按稳定玩家身份保存，不按昵称保存。名字改变不能导致钱丢失，重新入房也不能生成第二份资产。

## 11.2 交易只执行一次

每次出售／转账／切割生成唯一请求号。验证距离、当前持有状态、金额和状态版本；成功后消费旧状态、产生新状态，再把结果确认给客户端。重复请求返回原结果，不能再次发钱。

转账同时扣 A 加 B，不能先写一边后写另一边。切开消耗原石并创建子物品，保存来源关系；不能既保留原石又得到内部宝石。用整数货币，明确上限，拒绝负数、溢出、自转账绕过与重复操作。

## 11.3 断线与回档默认规则

主动离开矿区房间时，随身可抢战利品先落成一个由房主管理的包；基础工具和个人余额保留。意外断线使用短暂重连宽限，期间仍保留唯一资产记录；超时按掉包规则处理。不要让“拔网线”变成免费传送存金。

本地世界文件按 worldId 保存四人的资产。采用一致快照、临时文件写入后替换、保留数份最近备份，以及关键交易记录；确切存储方案在 M1 锁定。存档有 schemaVersion，更新先备份再迁移。崩溃可以有明确的最近未持久化进度窗口，但不允许一边回退物品、一边保留钱而造成复制。

房主是可信主持者，不承诺防范其自行改存档或修改程序；好友游戏不首发建设竞技级反作弊。隐藏原石内部内容不广播给所有普通客户端，但不能宣称恶意房主也看不到。

## 11.4 两条必须验证的不变量

同一个 itemId 在世界、背包、嘴槽、箱子和加工台之间，只能存在一份有效实体。转账前后所有参与账户的总额相等；出售与加工等有意增减财富的行为必须能在记录里解释。做轻量记录是为修复功能，不是扩展成金融级后台。

# 12｜建模与场景：从 AI 初稿到游戏资产

## 12.1 三类资产走三条最省事的路

**规则形道具：** 木箱、铲、淘盘、支架、桌子、简易推车，优先让 Codex 写 Blender Python 程序化生成。尺寸和结构可控，修改也可重跑；不必为每个木箱消耗 AI 生成额度。[S07][S08]

**通用环境：** 石头、树、草、木屋模块，优先用同风格的合法素材，或少量基础件变化组合。Kenney 提供可商用的 CC0 资产路线，但要保留每个实际下载包的许可。[S12]

**独特宣传道具：** 鼓嘴矿工头、荒唐的金牙展示、特色探测器或切石机，用已确认风格的概念图生成 3D 初稿，再由 Blender 清理。Meshy 为首选试用，Tripo 只作不满意时的替换，不一起订阅。[S09–S11]

## 12.2 一个资产的完整交付链

资产规格 → 原创概念参考 → 草模或生成初稿 → Blender 清理 → 统一单位和朝向 → 材质简化／UV → 碰撞体 → 导出 FBX／选定标准格式 → Unity 导入 → Prefab → 手持锚点／交互脚本 → 联机实测 → 许可登记。

“看起来像铲子”不是验收终点。必须能正常握住、打到合理位置、不会卡地面、其他玩家看到的动作一致。原始生成文件保留在 SourceAssets，游戏中使用清理后的资产，不把所有源文件都塞进构建。

## 12.3 风格与性能预算先统一

设定一个成年人卡通矿工比例、一套色板、统一粗糙度和阴影风格。画面识别依靠轮廓、工具大小、矿物颜色及少量高亮，不靠高面数。首轮建议目标：普通小道具约 500–3,000 三角形、角色约 8,000–15,000，纹理多数 512–1024，少数近景可用 2048；这些是本项目起始预算，不是硬件必然承诺。

资产检查记录三角形数、材质数、贴图大小、单位、枢轴、碰撞、抓取点和来源。AI 模型常需修拓扑和骨骼；一件道具反复修不好就简化设计或更换资产，不无限重生成。

## 12.4 场景不是一张生成图片

先用 Unity 灰盒搭走路尺度、视线遮挡、搬运路线、矿点和营地距离。四人试玩能产生发现、碰面、求助和追逐后，再替换模型。营地收购台、切石台和个人小屋要近到便于围观，又不要所有矿点都暴露在同一视线下。

新采区通过模块化布置和矿点种子变化产生差别；首版用有限地图设计配合随机矿点，不承诺自动生成无限好关卡。

# 13｜角色、动画与互动表现

先做一个统一骨架，四名玩家共用动作，只改变帽子、脸、衣服配色等。第一人称手部与第三人称身体可用分层模型；别人必须看得见你拿了什么、有没有鼓嘴、是否正在搬货。首版不追求完整第一人称身体 IK。

必要动作：待机、走跑、蹲、跳、挖、拿取、持小物、搬大物、挥铲、受击／晕眩、恢复、含物／吐出、操作切石台。先使用几组基础动作加程序摆姿，不为所有工具重做全套动作。

Mixamo 可作为基础人体动作来源，Adobe 说明可免费用于商业项目，但其 FAQ 同时写有中国地区账户限制。必须先验证你的账户是否适用；不能通过伪造账户地区来绕过限制。不可用时用合法动作包或 Blender 简单关键帧。[S13]

特殊动作的难点是握持、手穿物体和嘴部形变，不是动作数量。鼓嘴可用形变或独立几何变形；嘴槽关联的物品实体仍由游戏状态控制，不让一个动画自己生成第二颗金粒。

击晕时优先让玩家清楚看懂方向、短暂失控和恢复。音效、工具回弹、物品脱手、他人反应常比复杂战斗动作更重要。玩家恢复后的输入应及时生效，禁止用一段很长的不可跳动画惩罚他。

**每个动作的验收：** 本地看是否顺手；另一位玩家看是否理解；高延迟下是否提前／滞后到影响抢夺；换帽子与工具后是否穿模；持物时能否进入窄路和转身；被击晕与断线是否释放持有状态。

# 14｜音频、语音、界面与可访问性

音频分为工具反馈、角色反应、财富反馈、环境底噪与界面声音。先做能区分挖泥、碰金属、掉金粒、扫描强弱和开石结果的少量音效，再补装饰。环境声音不能盖住朋友说话。

Audacity 用于录制、剪辑、淡入淡出和统一响度；优先实录与合法音库。ElevenLabs 可补稀缺短音效，其当前 Starter 页面列价为每月 6 美元，商用权利与生成时计划、产品条款有关；不要把免费生成的音频先放进商用构建，再以为后来订阅就自动补齐授权。[S28][S29][S35]

**语音在原型先不阻塞，在垂直切片成为正式功能。** 外部语音用于最早朋友测试；正式版加入 Steam Voice 采集／压缩、网络传输、解压播放及距离衰减。Steam Voice 不替你发送音频，也不是完整的即插即用空间语音系统。[S17]

默认按键说话，支持输入设备选择、测试回放、个人音量、静音、说话图标。全队语音与近距离语音可由房间设置选择；不能依赖“玩家不能私聊”来支撑交易规则。嘴里藏矿可以让游戏内声音滑稽，但信息代价仍靠可见鼓嘴等规则。

首发界面：主菜单、存档选择、创建／加入房间、邀请、基础 HUD、工具栏、个人背包／余额、转账、出售、切石、商店／展示、设置、断线错误。避免开界面就遮住所有周围情况，给抢夺和交易保留现场感。

从第一天把文本放语言表，支持简体中文与英文。先完成文本和字体布局，关键术语由真人检查。支持按键重绑、字幕／提示、镜头晃动关闭、合理 FOV／灵敏度、音量分组、分辨率和帧率限制。扫描不要只靠颜色，也用节奏或图标表达。

# 15｜正常开发流程与阶段验收

## M0：立项、环境和自动化底座

**交付：** 独立工程、版本清单、AGENTS、基础场景、构建脚本、环境报告。**工具：** Unity、Codex、Git、Unity MCP。**你做：** 登录、安装许可、启动构建。**通过：** 在目标电脑能干净打开工程、运行、打包，Codex 能读真实 Console；没有来源不明的资产和无关旧项目文件。

## M1：联机技术原型

**交付：** 本地 2–4 实例、拾取／丢弃同一矿块、独立余额、一次出售、转账、存取档；随后接两台真实设备的 Steam 连接。**工具：** FishNet、Steam 适配、Test Framework。**通过：** 同时抢物只一人成功；重复出售不重复发钱；客户端断线重进不复制物品。**暂时不做：** 漂亮地图、吞咽、赌场、宣传片。

M1 未通过，不生产大量模型；同一问题反复出现时先固定最小复现，不用换引擎掩盖错误。

## M2：四人可玩灰盒

**交付：** 找矿、挖掘、大矿协作、检测、开石、出售、转账、短击晕、嘴槽；一条工具购买目标。**你做：** 组织至少两组真实朋友试玩，其中至少一组不由你持续讲解。**通过：** 玩家能自发发现→协商→搬运／背叛→结算→再次出发，第二次仍愿意尝试新办法。记录无聊、迷路、被欺负和掉线，而不只录笑声。

## M3：垂直切片

垂直切片是“一小段接近最终质量的完整游戏”，不是演示视频。**交付：** 一片正式场景、角色、工具手感、基础空间语音、完整菜单和持久进度；一段可复现的 30–45 分钟体验。**工具：** Blender、选定资产工具、音频工具、Profiler、OBS。**通过：** 新玩家能自行进入和完成闭环；异网四人正常游戏；核心场面能真实录制。未通过就不扩展第三个采区。

## M4：Alpha，功能与内容完整

**交付：** 1.0 必需工具、三个小采区、收藏／展示、经济表、基础本地化、迟加入／重连。Alpha 的含义是功能闭环齐全，仍可有已记录缺陷。**通过：** 从新档到最终目标有路可走；1、2、3、4 人均无人数锁死；资产与功能清单可逐项核对。

## M5：Beta、公开试玩和优化

**交付：** Steam Playtest／Demo、设置、网络错误反馈、存档迁移、性能优化、授权清单。Beta 重点是稳定性和体验，不不断加新系统。**你做：** 观察陌生朋友群，记录第二次开房情况。**通过：** 无已知阻断／资产复制／存档损坏问题；性能和网络矩阵有实测证据；新手无需开发者陪同。

## M6：候选发布、1.0 与维护

**交付：** 冻结构建、版本标签、回滚包、商店素材与问卷、发售定价、已知限制、反馈入口。**通过：** Steam 审核、首次安装到退出保存的完整验证、至少一份旧档升级验证。你人工确认发布；Codex 不擅自点击正式上线。

上线后先修崩溃、资产错误、连接问题和严重体验问题；内容更新按真实复玩需求排，不因“AI 生成很快”就不断塞新物件。

# 16｜测试：四类证据都要有

## 16.1 自动逻辑测试

货币加减与上限、转账守恒、重复请求、矿石拆分、原石固定内容、检测一致性、背包／嘴槽互斥、存档往返、版本迁移、断线资产归属。至少把每个已经发现的复制／丢物 bug 变成回归用例。

## 16.2 引擎运行测试

Unity Test Framework 的 EditMode 测试适合纯规则／编辑器逻辑，PlayMode 测试验证运行中的对象和行为；命令行可以产生测试结果文件。[S18] Codex 必须同时检查执行结果、用例数量和失败数，不能只看进程退出码。零个测试不算通过。

## 16.3 联机和故障测试矩阵

| 情境 | 验收重点 |
|---|---|
| 2／3／4 人，本地与不同网络 | 邀请、同步、独立账户、物品唯一性 |
| 两人同时拿／卖／切同一物品 | 只有一个有效结果，无重复发钱和消失 |
| 转账时断线／重复发送请求 | A、B 余额一致，不出现半笔交易 |
| 拿着矿／含着矿／抬大矿时离开 | 唯一资产状态保留，重连／掉包规则正确 |
| 晚加入房间 | 看到当前世界，而非重新生成一套矿物 |
| 房主退出／进程终止 | 正常退出保存；崩溃恢复一致，不承诺零回退 |
| 模拟 100／200 毫秒往返延迟和轻度丢包 | 不复制资产；交互可理解，超出范围要有提示 |
| 长时连续游玩、反复进出房 | 无持续内存增长、卡死、背包状态残留 |
| 中文系统用户名、非默认路径、旧存档 | 启动、读写、升级与错误提示正常 |

这些延迟和时长是测试条件，不是目前已实现的网络指标。

## 16.4 人类体验与性能测试

两类组都要测：熟悉你的朋友，以及彼此熟悉但不熟悉开发者的朋友群。将“朋友聊天本来就开心”与“游戏增加了有趣行动”分开记录。关注首次发现、首次协作、首次主动交易、被坑后重新参与、第二次主动开房，以及重复劳动比例。

性能目标先定为目标测试机 1080p、中等画质、四人场景尽量稳定 60fps；最终最低配置只能由实测决定。用 Unity Profiler 找 CPU、GPU、物理、网络与分配瓶颈；不能只给一个空场景平均帧率。自动截图和录像用于复现关键问题，不为无关文件名和装饰截图浪费开发轮次。

严重级别：P0 为崩溃／存档损坏／资产复制；P1 为进不了房／核心流程断裂／长期受控；P2 为明显反馈、UI、穿模与平衡问题；P3 为装饰。P0／P1 未清理，不发售。

# 17｜工时与排期：用工程量预算，不许愿日期

以下是本提案的粗略人工投入估算，不是行业统计，不是 Codex 独立运行时长，也不是对你个人速度的测量。已假设使用 AI、现成资产和受限范围，仍包含学习、联调、反馈和返工。

| 阶段 | 基准投入区间 | 决策点 |
|---|---:|---|
| M0 环境与底座 | 16–32 小时 | 工具是否实际可用 |
| M1 网络和资产原型 | 48–96 小时 | 技术不变量能否守住 |
| M2 玩法灰盒 | 80–160 小时 | 是否值得继续做游戏 |
| M3 垂直切片 | 120–220 小时 | 是否具有可展示的品质 |
| M4 内容与功能完整 | 220–380 小时 | 是否在范围内闭环 |
| M5 测试、优化与打磨 | 160–280 小时 | 是否可交给陌生玩家 |
| M6 发布准备 | 100–180 小时 | 是否满足发布标准 |
| 基准合计 | 744–1,348 小时 | 不含发售后长期维护 |

再留约 25%–40% 缓冲，预算上可按约 **1,000–1,900 小时**看待。每周 20 小时相当于约 50–95 周；每周 35 小时约 29–54 周。它反映的是完整可售范围，而不是第一次拿起铲子需要那么久。

M1 的极简联网玩具应先出现，M2 再形成朋友能玩的灰盒。通过前两个阶段后，用实际完成速度重新估算后续，而不是把今天的粗估写成上架承诺。

每阶段设置投入上限与复盘：若连续两轮已做明显修改的试玩仍没有主动复玩与新目标，优先调整或停止扩产。没有必要要求“绝不放弃当前方案”，也不能因为功能做了一半就假设剩余全部是简单美化。

# 18｜预算：支出上限与订阅使用时机

以下均为美元预算，未做人民币汇率换算；不含已有电脑、你的人工时间、既有 Codex／ChatGPT 订阅及税费。不是外包报价，也不是收益预测。

| 项目 | 规划范围／核验事实 | 购买时机 |
|---|---|---|
| Unity、Blender、Git、基础网络库 | 符合许可时可走免费／开源路线 | M0；引擎资格需确认 |
| Steam Direct | 官方每个 App 100 美元；达到规定的 1,000 美元调整后总收入可返还该费用 [S21] | 准备自己 AppId 测试时，不等全部做完 |
| 通用美术／动作／音效资产包 | 预留 100–500 | M2 证明方向后购买 |
| AI 3D | Meshy Pro 当前帮助页为 20／月；试用 2–4 个月约 40–80 [S09] | 资产规格确定后按月开，不先年付 |
| 可选 AI 音效 | ElevenLabs Starter 当前 6／月；1–3 个月约 6–18 [S28] | 集中补音效，不常年空订 |
| 专项修模／动画／联机审查 | 预留 0–1,500，必须另索实际报价 | 卡住关键质量时使用 |
| 存储、测试杂费、宣传和缓冲 | 随实际方案预留 | 不以大规模付费投放起步 |

**启动预算建议：** M0–M2 的新增非人工支出先控制在约 100–300；没有真实 Steam 测试前，纯本地更低也可。**可售小版本现金预算：** 可以先预留约 500–3,000，加 20% 左右机动；硬件或较多专业外包另算。不要把这当成“总成本只有几千元”，时间往往是更大的投入。

运行时无大模型，玩家每玩一局不会消耗你的模型 token。房主主持路线不要求你常租专用服务器；但后续仍有版本维护、客服、平台与软件条款变化的工作。Steam 中继不等于对任何场景无限免费基础设施的保证。[S16]

Meshy 免费计划、下载能力和付费资产许可不能混为一谈；本次其官方帮助页对免费计划的描述存在不同粒度，正式导出与商用以具体账户和资产适用条款为准。[S09][S10] 不把“生成过预览”当成已经获得可下载商用资产。

商业核算用公式：回本销量＝累计投入／平均每份净贡献。例如投入 3,000 美元、假设每份净贡献 6 美元，需要约 500 份；这只是算术情景，未包含人工成本，也不代表这种销量容易获得。最终净贡献取决于实际售价、地区、折扣、退款、平台分成和税务。首发售价可以测试 9.99–14.99 美元的定位，不在原型阶段拍死价格。

# 19｜发布、分发与获客流程

## 19.1 正常发布顺序

确认发行主体／银行与税务资料 → 开通 Steamworks、支付 App 费用 → 配置测试与构建 → 有真实可展示切片后发布 Coming Soon → 分批好友与陌生群体测试 → Demo／Playtest → 商店与构建审核 → 候选版本冻结 → 人工确认发售。

Steam 官方对首批产品列有支付费用后 30 天的等待期，以及 Coming Soon 至少公开两周的要求；商店和构建要审核。不要在游戏做好那天才开始处理发行账户。[S22][S23]

Steam Playtest 可用于测试分发，官方当前还列有实验性的朋友邀请功能，适合此类需要朋友成组加入的测试；具体开放方式以后台可用项为准。[S26] 不能把某个测试 AppId 的可用性当成你的正式分发许可；自己的项目应取得对应访问与测试授权。

## 19.2 宣传先证明卖点，不讲技术堆栈

主画面文案候选：“一起挖金，各自算账。”三段短素材分别展示合作后赖账、探测口袋／嘴里藏金、开石逆转。画面必须来自真实构建；AI 可协助概念设计、字幕、剪辑安排，但不能伪造未实现的玩法。

用 OBS 录真实四人局，DaVinci Resolve 剪辑；先做好清楚的封面、截图、简短预告和中英文简介，不先花钱拍一段与实机无关的电影。[S33][S34]

比较不同素材带来的点击、愿望单与试玩转化，但不把播放量、一次笑声或愿望单数等同于销量。观察有人是否真的拉朋友进来、第二晚是否重新开房。公开测试前先确保加入房间和核心经济不出错，否则宣传只会放大缺陷。

## 19.3 买断 1.0 优先，抢先体验不是筹钱捷径

当前目标是做一个受控、完整的小版本。若后来选择 Early Access，需要现有版本本身值得购买，并明确当前功能、未完成内容和存档变化风险。Valve 明确表示 Early Access 不是众筹，也不应靠承诺未来完成来卖一个仅有技术演示的产品。[S27]

正式发布包至少包括 exe、必需数据、第三方许可、清楚的版本号、崩溃／日志收集办法、已知限制。发布前保存对应源码提交和可回滚构建。补丁优先处理连不上、丢档、复制物品，不因素材生产快而不断加系统。

# 20｜商用权利与分级：只做必要工作，但不能跳过

**资产台账从第一件正式资产开始。** 记录资产名称、来源、下载日期、许可版本、是否 AI 生成、生成时账户计划、是否需要署名、原始文件与游戏使用位置。AI 供应商给出的商业使用许可不等于对第三方权利作无限担保，参考图也需要有权使用。[S10][S12][S29]

Unity 的 MCP 工具、Blender 脚本等开发工具与最终游戏内容分开管理。保留开源依赖许可证；付费素材不要上传到公开仓库供他人下载。品牌、游戏名、角色和音效不照搬竞品；工作代号 GoldCamp 不视为已完成商标清查。

**Steam AI 披露。** 当前内容问卷区分开发期预生成与游戏运行时生成内容；最终用到 AI 制作的模型、贴图、音效或其他玩家消费内容，应按实际问卷要求准确说明。此项目无运行时模型，就不虚构动态生成能力；也不要简单宣称“用了 Codex 所以全部内容都是 AI”或“没接 API 所以不需任何披露”。[S24]

**模拟赌博不等于所有地区都没有分级影响。** 例如澳大利亚对含赌场式模拟赌博的游戏有 R18+ 要求。无真钱购买／提现不自动消除此类分级问题。我们保留赌石和玩家间虚构筹码玩法，但具体内容如何分类要在上架目标地区核实，不能用改名规避如实申报。[S25]

角色击晕、抢夺、烟酒和卡通排泄也应按实际内容填写问卷。本文不作发行法律结论；涉及实际发行主体、税务、所在国家的商业活动资格时，需要在开收款账户前核验。不要因广泛合规讨论阻塞灰盒测试，也不要把此页完全拖到发售前。

# 21｜风险表与明确的删减顺序

| 风险 | 早期信号 | 对策 |
|---|---|---|
| 主业不好玩，只有整人有趣 | 大家不再找矿，只蹲收购点 | 先修工具、发现节奏、赚钱目标；必要时重设循环 |
| 朋友受欺负而不是开心 | 连续击晕、强者垄断、输一次不再参与 | 短控制保护、基础工具保底、房间自定义规则 |
| 网络物理失控 | 抬物抖动、推车飞走、多人看到不同位置 | 单一权威、稳定载货槽、简化驱动与局部视觉效果 |
| 资产或货币复制 | 同时操作出现多份物品 | 唯一编号、请求去重、一致交易与回归测试 |
| AI 美术风格混乱 | 每件看着都漂亮，合起来像拼盘 | 同一色板／材质／比例，优先统一资产包和程序模型 |
| 内容需求不停扩大 | 新玩法绕过当前验收 | 新想法进入 Backlog；每阶段冻结范围 |
| 新对话丢项目背景 | 同一故障反复解释、重写已有模块 | AGENTS＋STATUS＋测试证据，不以长聊天替代源码 |
| 只有朋友礼貌夸奖 | 试玩开心却无人第二次上线 | 用外部朋友群、无开发者主持测试、观察复玩 |
| 发售后无人维护 | 修复没有可重现构建 | 版本标签、旧包、存档样本、回归清单 |

**延期时先删：** 吞咽／厕所、复杂假货／屏蔽、传统赌场、真实绳索、复杂推车物理、自由建房、公开匹配、新平台、大型新地图。**不删：** 加房间的稳定性、矿物唯一性、个人资产、找矿和出售闭环、可读的抢夺反馈、稳定存档、基本设置。

新增创意必须回答：给玩家增加什么可观察的行动？能与哪两件已有工具互动？是否引入新网络／动画／许可负担？能否用现有状态实现？不满足就先放入候选区，不因描述有趣立刻开发。

# 22｜第一轮真正应该让 Codex 做什么

**不要现在把全文当成“一轮做完整游戏”的执行命令。** 首轮只做 M0，再把 M1 按可验收模块连续实施。完整提案提供方向；单轮任务负责明确完成。

第一轮任务应包含：确认是新的独立目录；读机器配置和已安装 Unity／Git／Codex；记录实际版本；建立最小 URP 工程；初始化明确的目录结构与文档；连接或验证一个 Unity MCP；生成一张地面、玩家占位体、几块矿石；创建构建与测试入口；实际打包启动；汇报证据。

不购买素材，不开模型 API，不接支付，不碰旧业务仓库，不写吞咽系统，不冒充已完成四人测试。若缺少 Unity 许可登录或安装权限，列出确切人工步骤，完成其余可做部分，不把“需要点击一下登录”作为放弃整轮工作的理由。

附件执行包提供可直接粘贴的 M0 Prompt、AGENTS 模板、里程碑任务模板、资产规格与测试清单。模板内写出的文件路径和测试脚本是要创建的交付，不是当前已经存在的工程证据。

第一轮结束时，你最应该看到的是：一个实际启动的 Windows 小场景、无未处理编译错误、可重复的构建入口、真实状态文件。第二轮再把两位玩家连接起来，争抢同一块矿。按这个顺序，代码、美术、游戏设计都能被不断推翻和改进，而不会一次堆成无法验证的大工程。

```text
  SourceAssets/              # Blender／原始图／音频，按大文件策略管理
  Tools/                     # 导入、构建、资产检查等脚本
  docs/{GDD,TDD,ROADMAP,STATUS,DECISIONS,TEST_PLAN,ASSET_REGISTER}.md
  Artifacts/                 # 本机构建与测试结果，通常不进普通 Git
```

GDD 是游戏设计文档；TDD 是技术方案；ROADMAP 是阶段计划；STATUS 只写真完成和真阻塞；DECISIONS 记录重要取舍。资产注册表可用 JSON／CSV，方便脚本校验。Library、Temp、Obj 等可再生成目录不提交；.meta 与场景／Prefab 的配套关系需要保留。[S19][S20]

**单轮任务模板。** 背景与当前基线；本轮目标；范围外事项；要修改的模块；验收条件；实际测试和构建入口；提交权限；必须报告的证据。不要让“自行 debug”变成可以私自删测试、改需求或重写全项目。

**缺陷模板。** 构建号；玩家数量；谁是房主；网络条件；复现步骤；预期／实际；日志／录像位置；是否影响物品与钱；最后一个正常版本。这样比一句“联机又坏了”更容易交给 Codex 修。

**资产模板。** 功能、尺寸、风格、面数／材质预算、枢轴、握点、碰撞、动作要求、导出格式、许可、游戏内验收。先写规格再生成，避免得到一堆好看却不能握住的模型。

**阶段退出模板。** 实现了什么；真实测试了什么；还没验证什么；人类试玩结论；花了多少投入；继续／调整／停止决定。保持一次真实可运行的提交比堆积几十页“已完成”汇报更重要。
